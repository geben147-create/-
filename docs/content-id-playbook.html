01

먼저 결론부터

시간을 아끼기 위해 조사 결과의 핵심 네 가지를 먼저 적습니다. 나머지 섹션은 전부 이 네 문장의 근거입니다.

현실 순수 AI 생성 음원은 대부분의 유통사에서 Content ID가 구조적으로 막혀 있습니다. RouteNote는 AI 콘텐츠를 Content Recognition 서비스에서 제외하고, Amuse는 Content ID·Meta 제외, LANDR은 Content ID·Meta·TikTok·Deezer·Pandora까지 제외합니다. 유통 자체는 되지만 Content ID만 빠집니다. "싼 유통사를 찾으면 된다"는 접근으로는 이 벽을 못 넘습니다.
예외 Symphonic Distribution은 AI 콘텐츠를 Content ID에서 제외하지 않는, 현재까지 확인된 유일한 중견 유통사입니다. Starter 연 $19.99(2026년 5월 신규 가입분부터 $29.99로 인상). 스트리밍 로열티는 100% 지급, UGC·소셜(YouTube Content ID·TikTok·Meta·Snapchat) 수익만 70/30으로 30% 공제. AI 업로드 수량 제한도, 플랫폼 제외도 없습니다. 대신 SymphonicMS 업로드 시 사용한 AI 툴·모델·회사를 공시해야 합니다.
해법 승인 확률을 실제로 올리는 유일한 방법은 최종 믹스에 사람이 만든 오디오를 넣는 것입니다. 업계 분류선은 "AI-generated(AI가 들리는 결과물을 만듦)" 대 "AI-assisted(사람이 만든 요소가 최종 녹음의 주된 부분)"입니다. AI-assisted로 넘어가면 TuneCore·CD Baby를 포함한 거의 모든 유통사가 열리고 Content ID 논쟁도 사라집니다. 3번 섹션이 그 방법을 확률 순으로 정리한 표입니다.
함정 AI 트랙을 Content ID 레퍼런스로 올리는 것 자체가 사업 리스크입니다. 같은 모델·같은 데이터셋에서 나온 트랙은 서로 스펙트럼이 닮습니다. 내가 올린 레퍼런스가 남이 독립적으로 생성한 유사 트랙을 클레임하고, 상대가 독립 창작을 입증하면 분쟁에서 집니다. 잘못된 레퍼런스가 쌓이면 레퍼런스 삭제를 넘어 파트너 자격 자체가 흔들립니다. 유통사 입장에서는 곡 몇 개가 아니라 계정 전체가 걸린 문제입니다.
02

Content ID 자격 요건

유튜브가 공개한 기준과, 유통사를 통해 우회할 때 실제로 요구되는 조건.

유튜브는 개인이 자기 계정에서 Content ID를 직접 신청하는 경로를 열어두지 않습니다. 반드시 공식 음악 파트너 또는 유통사를 경유해야 합니다. 공식 문서상 자격 요건은 "유튜브 사용자 커뮤니티에서 자주 업로드되는 원본 자료의 상당 부분에 대해 독점권(exclusive rights)을 보유"이고, 저작권 보호 콘텐츠에 대한 배타적 권리 증빙을 제출해야 합니다. 승인 후에는 독점권이 있는 콘텐츠만 레퍼런스로 사용한다는 조항이 들어간 동의서에 서명합니다. 이 한 줄이 AI 음원 Content ID 문제의 뿌리입니다.

  • 5만 곡 실적 없이도 Content ID 접근 가능

본인이 유통사라면 위 소비자 플랜을 쓰는 게 최종 답이 아닙니다. 자기 CMS를 갖는 두 갈래 중 하나를 골라야 합니다. (A) 유튜브 Preferred Distributor 직접 신청 — 사운드 레코딩·아트트랙 각 5만 건 납품 실적이 필요하므로 지금 당장은 불가능에 가깝습니다. (B) FUGA·LabelGrid·Believe 같은 상위 애그리게이터의 화이트라벨 채널을 빌려 자기 브랜드로 서비스 — 실적 요건 없이 Content ID 접근이 열리고, 대신 레퍼런스 품질 관리와 분쟁 대응 책임을 그대로 집니다. AI 카탈로그를 대량으로 태울 계획이라면 (B)에서 계약 전에 AI 음원 레퍼런스 등록 가능 여부를 반드시 문서로 확인하세요. 여기서 막히면 뒤의 모든 작업이 무의미해집니다.

BDAW 없이 Claude Code만으로 — 가장 싸고 빠른 경로

사실 3번 섹션의 "구조 재편성"과 "스템 분리 후 재조립"은 DAW 없이 전부 자동화됩니다. Claude에게 파이썬·ffmpeg 스크립트를 시키는 쪽이 GUI를 손으로 만지는 것보다 훨씬 빠르고, 무엇보다 25곡·100곡 단위 배치가 됩니다. 유통사 규모에서는 이게 결정적입니다.

# 1. 설치 — 전부 무료
pip install demucs matchering librosa soundfile pydub numpy
# ffmpeg는 시스템 패키지로 설치

# 2. 스템 분리 (보컬 재녹음용 인스트루멘털 확보)
demucs --two-stems=vocals -n htdemucs_ft ./in/*.wav -o ./stems

# 3. 구조 재편성 — Claude에게 시킬 작업 예시
#    "stems/ 안의 각 곡에서 후렴을 찾아 인트로 앞 8초를 훅으로 붙이고,
#     2절 뒤에 4마디 브레이크를 넣은 뒤 다시 렌더해줘"
#    → librosa로 비트·섹션 검출, pydub으로 재배치, soundfile로 출력

# 4. 레퍼런스 매칭 마스터링 (카탈로그 음압 통일)
python -m matchering ./mix/track.wav ./ref/reference.wav ./out/track_master.wav

# 5. 유통용 스펙으로 일괄 변환 + 라우드니스 정규화
ffmpeg -i out/track_master.wav -af loudnorm=I=-14:TP=-1:LRA=11 \
       -ar 44100 -sample_fmt s16 dist/track.wav

이 파이프라인에 사람이 부른 보컬 트랙 하나만 얹으면 3번 표의 최상위 항목이 충족됩니다. 나머지는 전부 자동입니다. 유통사 규모에서 실현 가능한 유일한 구조는 이것 — 기계가 할 수 있는 건 전부 배치로 돌리고, 사람의 시간은 오직 보컬·실연에만 쓰는 것입니다.

리스크 — 유통사가 특히 조심할 것

개인 아티스트는 곡 하나를 잃지만, 유통사는 계정과 파트너 자격을 잃습니다. 손실 규모가 다릅니다.

R1 AI 레퍼런스 충돌 — 가장 큰 위험 AI 트랙을 Content ID에 등록하면 다른 사람이 독립적으로 생성한 유사 AI 트랙까지 매칭합니다. 그 사람들이 분쟁을 걸고, 독립 창작을 입증하면 이깁니다. 같은 모델·같은 데이터셋에서 나온 결과물이 서로 닮는 것은 구조적 문제라 회피가 불가능합니다.
R2 잘못된 레퍼런스 삭제 · 파트너 자격 권리자가 배타적으로 통제하지 않는 콘텐츠의 레퍼런스는 무효로 간주되어 삭제됩니다. Content ID 사용 시 서명하는 동의서에 "독점권 있는 콘텐츠만 레퍼런스로 사용"이 명시돼 있으므로, 반복되면 계약 위반 문제로 넘어갑니다.
R3 저작권 경고 3회 = 채널 종료 저작권 경고(strike)는 영상을 내리고 채널에 90일간 표시되며, 3회 누적 시 채널이 종료됩니다.
R4 소급 집행 · 정책 변경 DistroKid는 2025년 전 업로드 자동 스크리닝을 의무화하고 2026년에 소급 집행을 도입했습니다. 유튜브는 2025년 7월 "repetitious content"를 "inauthentic content"로 개명하며 범위를 넓혀, 진짜 사람의 창의성 없이 정형화·대량 생산된 콘텐츠로 이루어진 채널 전체를 대상으로 삼았습니다. 오늘 통과한 것이 내년에 내려갈 수 있습니다.
방어 곡별 제작 기록을 남기세요 사용한 AI 툴·모델·버전, AI가 관여한 요소(가사·스템·마스터링), 사람이 만든 요소(보컬 녹음 파일·MIDI·연주 원본), 날짜. 분쟁이 생겼을 때 독립 창작과 사람 기여를 입증할 수 있는 유일한 자산입니다. 스프레드시트 한 장이면 충분하고, 이게 없으면 R1에서 무조건 집니다.
